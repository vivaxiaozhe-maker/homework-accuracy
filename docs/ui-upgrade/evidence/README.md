# UI 迁移证据规则与记录模板

本目录用于保存**目标实现**的可核查证据。任务包原型的截图、旧轮测试数字和源码存在证明都不能充当新 UI 通过证据。v1.15.0 最终实际验收汇总见 [`final-verification.md`](final-verification.md)。

## 1. 状态与证据纪律

- `NOT_RUN`：尚未执行，或只有计划/源码映射；当前 100 个迁移跟踪项均已执行，生产发布动作仍为 `NOT_RUN`。
- `PASS`：在指定目标版本、角色、环境和数据集中实际执行，步骤、预期、实际结果和证据齐全。
- `FAIL`：已执行且结果不符合预期；必须附缺陷链接/编号，不能改写为 `NOT_RUN` 或 `PASS`。
- `BLOCKED`：已尝试但被明确外部条件阻断；记录阻断原因、影响和下一步，不等于通过。
- 部分完成必须列出未覆盖子项，不能整项记 `PASS`。未实现、只演示、仅自动 DOM 断言、无法验证均不能记 `PASS`。
- 证据不得包含真实账号密码、session、微信密钥、完整分享 token、真实家长信息或生产敏感数据；截图前脱敏。
- 每条记录写明代码 commit/版本、日期时间、环境（mock/隔离 API）、数据集、角色、浏览器、执行人和实际命令。不要用“应该”“理论上”描述实测结果。

## 2. 文件命名与目录建议

```text
evidence/
  README.md
  AC-G01__<browser>__<role>__<viewport>__<seq>.png
  AC-T10__<scenario>__<result>.json
  FIX-R01__<scenario>__<result>.json
  commands__<batch>__<yyyymmddThhmmss>.log
  browser-matrix__<build>.md
  performance__<base|growth>__<browser>__<build>.md
```

- 矩阵项使用原 ID，例如 `AC-D08`；缺陷/依赖追加项使用 `FIX-R01`…`FIX-R06`、`FIX-S01`，避免与销售 `R01`、学生 `S01` 混淆。
- `role` 只用 `admin/ta/sales/parent`；`browser` 用实际浏览器和版本；`viewport` 用 `1512x716`、`1280x720`、`834w`、`390x844`。
- 截图序号从 `01` 开始；失败也保留原图，不覆盖。日志只追加实际执行结果，不手工编造命令输出。
- 自动断言、可见截图、真实 API 结果和性能数据分别保存；一种证据不能替代另一种。

## 3. 浏览器证据最小字段

每张图或每组录屏对应一条记录：

| 字段 | 填写内容 |
|---|---|
| 验收项 | `AC-* / FIX-*` 与具体子场景 |
| 构建 | commit、APP_VERSION、前后端版本 |
| 环境 | mock / 隔离 API；禁止误标生产 |
| 数据集 | 固定数据集名称、关键规模与业务日期 |
| 角色/账号标识 | admin/ta/sales；只用脱敏测试标识 |
| 浏览器/视口 | Chrome 或 Safari 完整版本；实际窗口尺寸 |
| 操作步骤 | 可重复的真实点击/输入/接口步骤 |
| 预期/实际 | 分别写，含计数、ID、顺序、错误与持久化结果 |
| 状态 | NOT_RUN / PASS / FAIL / BLOCKED |
| 附件 | 截图、日志、响应脱敏文件的相对路径 |

覆盖矩阵至少包含 Chrome＋Safari、admin/ta/sales、四种目标尺寸，以及保存成功/失败/慢响应、空/加载/错误、长文本、键盘焦点、Esc/焦点返回、滚动和缩放。自动 DOM 断言不替代可见检查。

## 5. 容量对照记录

- 固定规模：0/1/20/21 条与末页删除；基础约 400 在服务＋43 归档、200+ 待办、11 助教、40 科目、2500 成绩、20 待批；扩展 1000 在服务、10000 成绩、500 待办、50 科目、50 待批。
- 必含数据边界：跨 owner 同名、同日、归档/恢复、无作业、未交＋补交、空格子、零计划、未来开课/作业、已处理、并发冲突。
- 对照旧/新任务 ID 全集、顺序、各类计数、日期范围、均分、名单和权限字段；分页只改变展示，不能改变全量统计。
- 任务包 `05-合成数据场景与核验.json` 只证明其 fixture 结构检查为 PASS，`browserCapacityTest` 仍是 NOT_RUN；不能转写为本项目浏览器容量通过。
