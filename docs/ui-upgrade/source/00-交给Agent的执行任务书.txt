【发给执行 Agent 的任务】
请在现有学情系统中实施已确认的 UI 升级。以本任务书、93项功能对照矩阵及执行时最新线上功能为业务依据，以“参考原型”作为视觉参考。必须保持现有功能、数据、角色权限、接口契约、统计口径和外部链路完整。

首要事实：现有 React 原型不是线上系统的完整实现。它遗漏了多个看板模块和审批、模考、报告等流程，使用内存示例数据，不能直接覆盖生产入口，不能作为精简功能的授权。页面看起来完成、构建通过、原型的design-qa通过，均不代表业务迁移完成。

本任务优先于此前UI源码包中与功能范围冲突的说明。之前写过“首页/看板等已完成”，仅指视觉原型；之前将“账号删除”描述成新增需求已过时：当前基线已有账号删除影响预览、服务端事务删除和墓碑记录，必须保留并完善呈现，不能重复实现一套简化逻辑。

本任务不包含生产发布授权、生产数据变更、真实通知发送或真实账号/学生清理。不得援引旧AGENTS里的“小改直接部署”替本任务获得生产发布授权。完成本地/测试环境验证后提交可审阅的变更、证据和回滚方案，待明确发布授权。

5. 完成/搁置/稍后后，在服务器确认成功再出清当前行，计数与当前页同步；最后一页空了回退有效页，不跳到别人的记录。失败保留原行和输入。
6. “已处理事项”默认收起，但显示总数并提供分页/筛选。主任务列表不要通过硬裁切、只取slice前N条而没有入口隐藏其余任务。
7. “最近动态”可作为辅助区域，限定5条左右并链接操作记录；不能用其替代任务/审批。大量数据时主工作区采用完整宽度或主次列响应式，不允许两列任务行挤成多行按钮墙。

【原有口径必须区分】
- 首页待办未交会排除done/shelve/当日snooze；看板未交总量可包含这些底层记录。176和185不要求机械相等，名称要说明“待处理”与“未补交总量”。
- 未交不随过几天自动升级为逾期。逾期按科目计算：已开课 + 有计划欠账 + max(最近成绩日、最近未交登记日、计划设定日) 距业务今天超过全局周期。days等于周期不算超过；无计划/未开课/已完成/无活跃信息不算。继续复用subjectOverdueInfo。
- 稍后当天有效、次日再现；完成/搁置保留原记录和回溯；kind/refKey兼容原alert_actions，不能换新key导致旧已处理事项复活。
- 首页低分当前按近7天正常成绩、学生×科目聚合，代表条目取该科目最低记录；看板低分是范围内平均。现有部分说明将前者写成“平均”，不得擅自用同一个平均算法重构两者。可先用准确文字解释，算法变更另行确认。

五、原型里尤其不能直接迁移的简化模型
1. 原型plan是学生单值；生产是学生×科目的subjPlans/subjPlanSetAt/subjFirstClass，不能丢映射。计划0合法，已有计划二次修改保留申请/撤回/审批，不把原型min=1带过去。
2. 原型notes/advice在学生级；生产评语/建议在学生×科目级，不能跨科目覆盖。未提交的空字符串也是有效草稿；按用户/学生/科目/记录身份隔离。
3. 原型新增学生缺毕业年份并可选择硬编码助教；生产毕业年份必填，新增归当前用户，转移归属仅走教务明确操作。
4. 原型只有最近记录表；生产有完整打卡槽位、空位、超计划记录和稳定refId/refType。不能用日期/数组下标或学生姓名替代真实ID。
5. 原型账号可选“教务”只是演示偏差；当前创建入口仅助教/销售。不能在UI升级中新增创建教务权限。
6. 原型删除只查学生数；当前后端已有7类关联阻断、事务内重检、session吊销、tombstone、审计和用户名永久不可复用，全部保留。
7. 原型CSV导出不能取代线上JSON业务数据导出；JSON本身也不是包含附件/系统配置的整站恢复包。
8. 原型只实现会话内数据、固定日期和模拟延迟；不得复制其保存、身份、日志、设置或角色行为替代真实API。
9. 原型对错题数必须完全匹配的限制更严格；生产既有分隔符/校验行为必须核对，不凭设计稿新增阻止保存的规则。未来开课/模考允许；未来作业日期的策略按R05业务确认，不能一律禁止所有未来日期。
10. 原型历史页仍有可编辑笔记演示，不能作为历史学生只读权限依据。
